Key findings

Evidence labels matter. “VM demonstrated” means the target game build exercised the behavior. “Build/test only” means code compiled and automated checks passed, but the game lifecycle was not completed.

Homecoming was resolved and made authoritative

Runtime lookup resolved arcade_homecoming to registered activity indices 37 and 38. Replacing a copied descriptor at the verified normalization boundary made the client request and start Homecoming.

The host recognized a joined Homecoming arrival

VM demonstratedSession

The retained cycle recorded a connected bridge, active and joined activity session, worldPhase=arrived, package arcade_homecoming, and 151 held entity slots.

This was a reliable policy gate. It did not prove those slots could be turned into valid enemy actors.

A real objective.set adapter was never recovered

MissingObjectives

Definition lookup, completion and progress readers, switch banks, and several application helpers were localized. The normal host-to-client producer and Homecoming objective-to-runtime-index mapping remained unknown.

Static identities such as obj_ghaul, obj_damaged, obj_deck, obj_shield_gen, and obj_deck_ultra do not establish runtime indices or a valid wire payload.

Correct conclusion: consumer paths found; producer not found.

Enemy spawning and AI were not implemented

MissingEntities / AI

Placement catalogs and entity-slot leases existed, but no verified actor baseline, authoritative creation funnel, simulation/AI binding, health and death replication, or clean removal path was completed.

A spawn point plus a free entity slot is not a working enemy.

The original Red War mission policy was not recovered

MissingMission policy

The client exposed content identifiers, state consumers, and package relationships—not Bungie’s original host-side sequencing, encounter policy, or authoring source. Any C# scenario graph was an authored reconstruction.

Observed incidents were not safe to replay

HypothesisTransport

The source-to-wire body boundary was correlated, but target meanings and application-payload semantics remained opaque. Observation was justified; emission was not.

A local hardening line made restart behavior safer

Build/test onlyHardening

Protocol v2, deterministic execution IDs, checkpoint schema 2, native deduplication, transactional plugins, cycle limits, and exact activity-session matching passed clean managed/native builds and automated tests.

The best remaining path was the normal state producer

HypothesisObjectives

A future restart should correlate one legitimate objective transition through the normal decoded/global-state producer, then map Homecoming definitions into the consumed bank. More direct memory writes would not resolve the missing semantics.

Research timeline

Foundation

Built an out-of-process .NET host, bounded native pipe, deterministic authored scenario graph, and explicit unsupported-capability boundary.

Observation

Verified world-phase and incident observation and separated copied scalar evidence from unsafe retained engine state.

Homecoming

Resolved registered indices and made arcade_homecoming authoritative through the client’s in-world start boundary.

Mutation probe

Changed gameplay-switch index 246, demonstrated persistence, and rolled it back while retaining exact binary evidence.

Hardening

Clean-tested restart-safe protocol/checkpoint work locally; no completed VM lifecycle matrix.

Archive

Consolidated the pushed experiment under slophost-experiment and stopped development.
