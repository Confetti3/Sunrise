00 / SUMMARY

Bottom line

The experiment found a real path into Homecoming’s activity state and proved one persistent gameplay-switch mutation. It did not recover a safe objective producer, an enemy actor lifecycle, authoritative AI behavior, or Bungie’s original host-side mission scripting. The later hardening line improved reliability in clean builds, but never completed the full VM lifecycle matrix.

01 / RESULTS

Key results

The four findings worth carrying forward into future Sunrise work.

Homecoming activity identity was solved far enough to start the correct activity

Runtime lookup resolved arcade_homecoming to indices 37 and 38. Replacing the full descriptor at the verified assignment boundary made the client request and start Homecoming instead of Tower.

runtime demonstrated

One retained gameplay-switch value could be changed, verified, and undone

A direct command changed definition index 246 from 0 to 2. Immediate, one-second, and five-second reads remained 2; rollback restored 0.

runtime demonstrated

The native/C# bridge observed real runtime events without passing game pointers

The bridge exchanged bounded JSON, observed world-phase transitions, and delivered a real activity incident through the native-to-managed path without making game threads wait on C#.

runtime demonstrated

The hardening line addressed the main restart and duplication hazards

Protocol v2, deterministic execution IDs, checkpoint schema 2, result deduplication, transactional plugins, cycle limits, and exact activity matching passed clean managed/native builds and tests.

02 / PROVEN

What worked

Open an item for the evidence boundary and the part that remained unsolved.

A
Authoritative Homecoming selection — the client activity descriptor was corrected before the host request was formed.
evidence

Changing only the server destination was insufficient because the client had already selected Tower. The experiment located the earlier descriptor assignment, copied the payload, replaced both indices, and wrote arcade_homecoming into the fixed name field.

The retained run logged an override from Tower index 20 to Homecoming index 37, followed by an activity-host request and in-world start naming arcade_homecoming.

Boundary: the client reached the correct activity-start state, but rendering remained a black frame. Correct identity did not activate the encounter.

B
Exact arrival observation — the host recognized a joined Homecoming session at the arrived phase.
evidence

The retained cycle observed an active joined session, package arcade_homecoming, worldPhase=arrived, and 151 held entity slots.

Boundary: entity-slot ownership is not actor construction. It did not prove an enemy could be created, simulated, damaged, replicated, or removed.

C
Read-only transport path — real phase and incident observations crossed from the game to C#.
evidence

A Tower control observed loading step 33, in-world step 38, and one incident with primary target 1121 plus five extras. The native queue copied bounded scalars and discarded stale rows on reconnect.

Boundary: an EDZ control produced the same target list with a different body, ruling out target 1121 as a Tower-specific objective identifier.

D
Persistent switch-state mutation — one live retained value was changed and restored.
evidence

The command wrote 2 to switch definition index 246. Three later reads retained the value, and a second command returned it to 0.

This is the strongest mutation evidence in the archive because it includes read-before, write, repeated readback, source identity, and rollback.

Boundary: the experiment did not establish which Homecoming objective, if any, index 246 controlled.

03 / LIMITS

What remained missing

These are the systems that prevented the experiment from becoming a mission host.

01
No safe objective mutation adapter — readers and internal helpers were found, but not the normal producer or Homecoming mapping.
unresolved

Definition lookup, completion and progress readers, switch banks, progression rows, and application helpers were localized. The missing pieces were the normal host-to-client producer and the mapping from Homecoming package definitions to live runtime indices.

02
No enemy actor lifecycle or AI — placement data and leases were not enough to create a functioning combatant.
absent

A complete path still needed archetype binding, authority, creation baseline, component binding, navigation, combat policy, health/death replication, and clean removal. None was demonstrated.

03
No justified incident replay — the body reached the wire, but its targets and payload semantics remained opaque.
unresolved

The client source-to-wire boundary was correlated, but that did not make any captured incident safe to synthesize or replay.

04
No recovered original Red War script — the client contained data and consumers, not Bungie’s absent host policy.
absent

The JSON scenario was authored experimental policy. It was never evidence that the original mission script, encounter composition, or AI direction had been recovered.
